## 🇨🇳 中文

把 PRD、原型、网页、接口、代码、测试记录和多轮上下文，转成可追踪的 QA 基线、风险用例、执行证据、Bug 与发布判断。适用于 Web/API/App/小程序测试、回归、热修复、测试方案、Bug 复核和 QA 收口。开工先建立请求契约与上下文卡，再做输入基线与风险设计，按路由走最小路径与受控工作流。用户指定 Markdown、Office、在线文档/表格/PPT 或飞书载体时严格服从，未指定时默认创建与内容匹配的在线载体。纯开发实现、纯排版和无测试目标的数据分析不触发。

### ✨ 能做什么

- PRD/原型/接口 → 可追踪的 QA 基线与风险用例
- 开工先建请求契约与上下文卡，对齐再测
- 输入基线与风险设计，让测试方案有据可依
- 覆盖 Web/API/App/小程序：功能、回归、热修复
- 输出执行证据、Bug 记录与发布判断
- 载体可选 Markdown/Office/在线文档，未指定则自动匹配

## 🇬🇧 English

Turns PRDs, prototypes, web pages, API specs, code, test records and multi-turn context into a traceable QA baseline, risk-based cases, execution evidence, bugs and a release decision. It covers Web/API/App/mini-program testing, regression, hotfixes, test plans, bug re-verification and QA sign-off. Work starts by fixing a request contract and context card, then input baselines and risk design, following a routing map and controlled workflow. When the user names Markdown, Office, online doc/sheet/slides or Feishu carriers it obeys strictly; otherwise it creates a matching online carrier by default. Pure implementation, pure formatting and data analysis without a testing goal do not trigger it.

### ✨ What it does

- PRDs, prototypes and API specs become a traceable QA baseline
- Fixes a request contract and context card before testing starts
- Input baselines and risk design keep the test plan justified
- Covers Web, API, app and mini-program: feature, regression, hotfix
- Outputs execution evidence, bug records and a release call
- Delivers in Markdown, Office or an online carrier, auto-matched by default
